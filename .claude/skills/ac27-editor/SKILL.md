# AC27 Editor — Repo Skill

## Project Identity

- **Name:** `ac27-editor`
- **Purpose:** Cross-platform desktop level editor for Airport Control 27 `.acl` flight schedule files
- **Stack:** Electron 33 + React 19 + Vite 8 + zustand 5
- **Entry:** `electron/main.js` (Electron main process) + `src/main.jsx` (React renderer)
- **App ID:** `com.ac27.editor`
- **MCP Integration:** Built-in HTTP API server (port 31415) + MCP tools for AI agent control (see `ac27-editor-mcp` skill)
- **Cloud LLM Chat:** In-app chat panel powered by DeepSeek / Gemini / Claude / Codex — 4-vendor multi-model chat with tool calling (see `references/mcp-integration.md`)

**Map Windows (separate BrowserWindow instances):**
- `electron/main.js` manages `groundMapWindows` / `airMapWindows` / `flightStripsWindows` Maps (keyed by ICAO) + `selectedCallSigns` Map (synced selection state)
- Each map window loads the same Vite SPA with query params (`?window=groundMap&airport=XXXX`, etc.)
- `electron/udp_listener.js` listens on `127.0.0.1:20266` for binary aircraft telemetry (10 Hz) and sends commands on `127.0.0.1:20267`
- Live aircraft state pushed to all open map windows (ground + air + flight strips) at 200ms interval via `udp-aircraft-state` IPC event
- Map window click-to-select goes through centralized `select-aircraft-in-map` IPC
- **Radar rendering:** AirMapWindow applies **display-level STAR/SID dedup** (`src/utils/starDisplay.js`): ZGSZ-style airports name each runway variant separately (e.g. `SAREX4.34L/34R/33/16L/16R/15` all the same STAR base) — `dedupeStarPathsForDisplay` merges them under the base route name (representative longest path + all served runways) for rendering/labels only; underlying per-runway cache keys stay intact for aircraft lookup / game save. Then `filterDedupedStarPathsByRunway` filters merged groups + preserved per-runway variants by the active runway set. GroundMapWindow computes an **auto-fit `contentViewBox`** over the fetched taxiway/stand/runway/area geometry (airports authored far from the world origin like ZGSZ would otherwise show a blank origin-centered box), falling back to `GROUND_MAP_CENTER_OFFSET` + `dataBounds`, and snaps the radar view to the airport once geometry arrives.
- **Patch command composer (`FlightPatchCommandBar.jsx`):** when a strip on the approach channel (`controlSeat=5`) is selected, a command-line-style composer pops up above the strips bar. Click/drag-driven options: `Fly Heading` (heading-only override — opens a 001–360 slider defaulted to the aircraft's live telemetry heading via `atan2(noseDirection.x, noseDirection.z)`, no fixed value list), `Fly Altitude` (1000-ft slider, hidden without live telemetry; China `Z*` airports — `isChinaIcao`, the same Z-convention `flightDefaults` uses for the 'zh' language — switch to a 300–2700 m slider in 300-m steps, converted back to feet before Send), `Fly Speed` (180–240 kt slider, hidden without live telemetry), `Fly Waypoint` (the aircraft's current-approach waypoint list from the STAR telemetry and the approach cache `_starWaypoints`, left-to-right in route order entry→IAF; picking a fix sends `update_heading` at the bearing from the aircraft's LIVE position to the fix, recomputed at Send — byte-identical to the voice pipeline's "fly direct to X"; OVERRIDES a composed Fly Heading, blacking it out), or `Clear for Approach` (supersedes the whole composed chain). Each panel's **Add** chains commands; **Send dispatches the chain IN ORDER — N sequential `send-patch-command` frames to the AC27Approach plugin** (see the `ac27-approach` skill). Heading/waypoint frames carry a fixed rate of 3°/s of game time (`TURN_RATE_DEG_S` — the plugin's `update_heading` smoothing; for `clear_for_appr` it drives the bounded de-snap: the nose rotates toward the IAF at that rate until capture, then the game's steering flies the final turn). Gated on `checkCommandCapability`/`checkBepInEx` (plugin only exists with BepInEx installed) + `witchMode` off; Escape/Cancel dismisses. Approach-only: aircraft handed to tower (seat 3) lose the popup automatically
- **Voice command input (live, patch-command vocabulary):** `useVoiceCommands.js` + `VoicePTTButton.jsx` provide push-to-talk voice commands for the Flight Strips window. Callsign-first flow: spoken airline name → ICAO code (via `AIRLINE_CODE_MAP`) + spoken numbers → digits → match against UDP aircraft → greedy pattern match against the patch-command vocabulary (heading/altitude/speed/clear-for-approach/fly-direct-to-waypoint, EN + ZH). **Speech backend: offline vosk** — `electron/voice-stt-vosk.js` (spawned by `electron/voiceSttWorker.js` via `process.execPath` + `ELECTRON_RUN_AS_NODE=1`), mic capture by sox (`bin/sox`, default recording device, 16 kHz mono), decoding by koffi + vendored `bin/vosk/libvosk.dll` (`electron/voskFfi.js`), **grammar-constrained** to the patch vocabulary (`electron/voice-grammar.json`, generated from the live parser tables — EN words + ZH chars), **dual EN/ZH** models with confidence-winner picking. The earlier Windows System.Speech PowerShell worker and the Web Speech API (broken in Electron — Chromium streams mic audio to Google's speech API, shut down for shell environments) are gone. Fuzzy matching (`voiceFuzzy.js` + acceptance table) remains as post-processing safety net. Full docs in `references/map-windows.md` "Voice Command Input"; `scripts/fetch-vosk-model.mjs` downloads the models (gitignored); `scripts/voice-stt-test.mjs` is the TTS round-trip harness. The voice build ships the LARGE en model (`vosk-model-en-us-0.22`) and the small zh model (`vosk-model-small-cn-0.22`).

Dismissal persistence (`STORAGE_KEY_APPROACH_PROMPT` in `src/utils/constants/ui.js` = `ac27_approach_prompt_dismissed`) is **state-scoped**: `'missing'` or `'outdated:<md5>'` — dismissing one outdated build still re-prompts for the next release. i18n: `mod_prompt_*` keys (zh + en in `src/utils/i18n.js`), Cancel reuses `modal_btn_cancel`.
- **Level reset:** `BrowserScreen.jsx` header has **Restore All** (`browser_restore_all`, `IoRefreshOutline`) immediately to the right of Background Video. - **Post-update nudge:** `electron/updater.js` writes `post_update_pending.json` in `userData` inside `installUpdate` (before `app.quit()`; dry-run gated by `AC27_UPDATE_MARK_PENDING=1`); `electron/main.js` exposes `check-post-update-pending`/`clear-post-update-pending` (`electron/preload.js`); `src/App.jsx` after boot (`booting` false, not `prompt`/`downloading`/`installing`, no modal open) checks once via `checkPostUpdatePending` and shows one-time modal `update_post_title`/`update_post_body` (`AC27Editor已更新，若任意存档曾经被修改，请还原所有关卡文件。` / `AC27Editor Updated, if any level file was modified, please restore all level files.`) with **Cancel** (`modal_btn_cancel`) | **Continue** (`update_post_continue`). - **Ground Painter:** dedicated full-screen window to edit a level's **static scenery** (taxiways, runways, areas, stands) against an **id-free Graph**. Entry: `EditorScreen` toolbar button (`IoPencil`, i18n `toolbar_ground_painter`) → store `toggleGroundPainter` → `showGroundPainter` portal (`src/components/EditorScreen/GroundPainter/` — `GroundPainter.jsx`+`.css`, `GroundPainterToolbar.jsx`, `snap.js`, `fillet.js`, `metrics.js`). Read path `src/acl/scenery_graph.js:buildSceneryGraph` runs in the **main process** (`load-ground-painter-data` IPC, because the renderer can't reliably dynamic-import the CJS acl module); write path `src/acl/scenery_write.js:patchSceneryBlob` via `save-ground-painter-data` IPC (`.bak` + `writeAcl`, returns the new baseline). Edits are **in-memory only** until Save (confirm prompt, `.bak` checkbox default on) / Cancel (discard); the painter renders as a **full-screen fixed overlay** (`z-index:9999`) that **covers** the editor UI — so on-screen flight/timeline interaction is visually blocked, but the MCP API is **not** gated (`create_flights`/`modify_flights` still run); depth-1 `Ctrl+Z` via paired `groundPainterHistory`/`groundPainterMetaHistory` (`appStore.js:setGroundPainterGraphWithMeta`). Snapshot is only `currentPath` (a **per-level subset** — see the v5 note), so **no cache invalidation** is needed. MCP provides **full toolbar coverage** in `electron/api-server.js` (documented in `ac27-editor-mcp/SKILL.md` §10 — all tools push paired history, deduplicate nodes, and record `meta.deletedPks`/`deletedAreaIds` so saves persist): `get_ground_painter_state` (read), `create_taxiway_lines` (taxiwayLine D), `create_taxiway_fillet` (curve F — connected + virtual, radius 0.5..5.0, ghost repair), `create_runways` (runwayLine R — heading-derived names + Flags=4 pavement strip + `meta.runwayPavement` coupling), `create_areas`/`create_area` (area G — 0|1|2, bulk+single), `create_stands` (stand H — nose+tail, heading 1..360), `delete_ground_objects` (point-priority stand>segment/runway>area, orphan GC), `undo_ground_painter` (paired graph+meta). Runway end names (the designators on each threshold, e.g. `27`/`09` or `27L`) are edited **only via floating on-canvas text boxes** (`runwayOverlay` in `GroundPainter.jsx`) — not the toolbar — each a **plain 3-char `type="text"` input (`maxLength={3}`)** with **no in-place validation**, so a box can be cleared to empty while typing; the `DD`/`DD[A-Z]` format (two digits, optionally one capital letter) is validated on **Save** (invalid names block the save and show `ground_painter_validation_runway_name` via `setGpError`). The toolbar has **no** runway end-name editors. The global `keydown` handler ignores `Delete`/`Backspace`/`Escape`/`Ctrl+Z` whenever focus is in a text/edit field (`isTextEditTarget` in `GroundPainter.jsx`), so typing or clearing a name box never deletes the selected runway. **Runway-vs-pavement selection:** in the Select tool, `taxiway-segment` strips whose `Name` === a runway's `physicalName` (ZSJN runway `01/19` ↔ strips named `"01/19"`) are skipped from the segment candidates — a click on the runway always selects the runway, while connector taxiways that just meet it (A, B, C…) stay selectable. A normal editor save after a Ground Painter save does **not** revert scenery — the flight-save pipeline re-reads the file from disk and replaces only the flight-plan entry range (the editor's in-memory `vals` stay stale until the level is re-entered). Full internals in `references/acl-format.md` "Ground Painter — id-free Scenery Graph".

- **Ground Painter area-type toolbar toggle (no dropdown):** when the Area/polygon tool is active, `GroundPainterToolbar.jsx` shows a **3-button toggle popover** (`.gp-areatype-group`) that pops up **above the highlighted polygon button** (`.gp-area-wrap` wrapper). Buttons: `PiSelectionThin` → boundary (`ground_painter_area_boundary`, 边界/Perimeter), `FaParking` → apron (`ground_painter_area_apron`, 停机坪/Apron), `FaBuilding` → building (`ground_painter_area_building`, 建筑/Building). Only one is active at a time; the default `areaType` in `GroundPainter.jsx` is **2 (Building)** (`useState(2)`). Clicking a toggle calls `onAreaType(value)`; the popover renders only while `tool === 'area'`.
- **Ground Painter stand icon & select priority:** Stand plane icon is **fixed on the map** (world size `baseDiag*0.028/2.4` ≈ `0.522 GU` for ZSJN — the size it had at 240% zoom), not screen-constant (`getDynamicSelectThresholds`, `GroundPainter.jsx:30-43`; render/hit-test use `fixedWorldSize/512` and `fixedWorldSize/2` at `:2948`/`:3240`). Select hit-test is **dynamic**: `getDynamicSelectThresholds(viewBox,baseVB)` computes `scale=vbDiag/baseDiag` (<1 when zoomed in) and `TH=max(worldSnapDist(vbDiag),0.45)*scale`, `TH_STAND=fixedIconHalf*1.35*scale`, `tightStand=fixedIconHalf*0.75*scale` — so the world/screen area covered by the snap shrinks when zoomed in, freeing the apron/building under a stand. **Stand has higher priority than taxiway**: `bestStand || bestLine` (stand wins over segment/runway when both in range); area vs stand uses `tightStand` — interior area wins if `standDist>tightStand`, otherwise precise stand wins. **Stand does not snap** (`GroundPainter.jsx:1122` and the placement/drag paths): `TOOL_STAND` preview (`onMove` early `setWorld(raw)`), placement (`onClick` `nose=raw`) and body drag (`applyDrag` `dx=raw-startWorld` early return) all use `raw` cursor, not `findSnap`, so moving a stand is free.

- **Ground Painter fillet — disconnected (virtual) fillet is additive, never deletes taxiway:** The virtual path is **additive**: `applyVirtualFillet(g,m,res,segIdxA,segIdxB)` + `attachVirtualFilletLeg` (`fillet.js`) wire each picked segment to its tangent point without removing anything — (a) a node already sits at the tangent point (endpoint, or interior node of a multi-vertex polyline → split at that node so the branch is a real junction); (b) tangent beyond the near endpoint (the common gap case) → original segment untouched + extension stub `[T→near]` bridges the gap (original PK survives verbatim); (c) tangent strictly inside the span → segment split at the tangent point into `[near..T]+[T..far]` (original PK ghost-deleted, geometry fully preserved by the pieces, arc branches at T). The arc is appended with its endpoints anchored at the (possibly pre-existing) tangent nodes, so only interior arc points become new nodes. Connected fillets keep the truncation semantics (the corner region IS the rounding). `computeFillet` returns `ground_painter_fillet_error_parallel` for parallel/collinear-disjoint picks, and `commitFillet` early-returns on `!res.ok`. Preview draws dashed `tangent→near` connection legs for virtual picks instead of the truncated `far→T` legs. Tests: `tests/components/EditorScreen/GroundPainter/fillet-virtual.test.js` (+ `fillet-connected.test.js` for the connected/truncation path).
- **Ground Painter — ghost-node invariant: a NEW entity must never reference a node that will not be written:** a node whose original PK was pushed into `meta.deletedPks` is a **ghost** — deliberately kept in `graph.nodes` so every other entity's index stays stable, but dropped from the `.acl` by `patchSceneryBlob`. A **new** entity (one the writer re-synthesizes, i.e. `meta.segOrigPk`/`standOrigPk`/`runwayOrigPk` is `null`) that still points at a ghost index serializes to `"$iref:null"`, which the Odin JSON reader rejects (`invalid $iref payload "null"`) and which **aborts the whole Ground Painter save**. `fillet.js` exports `ghostNodeIndices(graph, meta)` (the ghost index set) and `repairGhostRefs(graph, meta)`: the latter re-points new segments/stands/runways onto a **live node at the same coordinate** (duplicate nodes at a snap point are geometrically identical, so the shape is preserved) and drops entities that cannot be repaired — **survivor entities are deliberately never touched**, because the writer copies them verbatim and editing their indices would silently not persist. `commitFillet` calls it right after ghost-deleting the O nodes (at a T junction the arms often use co-located twins), and `save()` calls it again as a guard — a repair there is logged with `console.error` because it means an earlier edit left the graph inconsistent. Returns `{remapped, dropped, warnings}` where `warnings` are i18n keys. The writer is the second half of the defence: `_synthesizeSegment`/`_synthesizeStand` **return `null`** (caller drops the entity) instead of emitting a null node ref, and new segments/stands whose endpoint nodes no longer resolve are skipped with a warning. Covered by `tests/integration/ghost_ref_invariant.test.js`.
- **Ground Painter — survivor dangling-`$iref` gate + last-resort validation:** deleting a taxiway node in the painter drops it from the `.acl`, but **survivor** entries are copied verbatim — so a survivor `taxiway-segment`/`stand` still holding a `$iref` to it serialized an unresolvable reference that the game's `TaxiwaySegment2DFactory` null-derefs on level init (the ZSJN_leisure_1 crash: `$iref:2004`/`$iref:2040`). `patchSceneryBlob` now runs `_gateSurvivorDanglingRefs` **before** the jetway cascade, repairing each survivor in order: (1) **rewire** the dead ref to a live `taxiway-node` at the same coordinate (co-located junction twins are geometrically identical); (2) **excise** the ref from the entry's `$rcontent` list when ≥2 refs remain — `_exciseIrefFromRcontent` also decrements that list's `$rlength` (the last `"$rlength"` **before** the `"$rcontent"` key), and returns `null` for a ref that is a bare property (a stand's `NosePosition`/`TailPosition`), which falls through to the drop path; (3) **drop the whole entry** — its ids join `deletedIds` first, so a dropped stand's jetways cascade too. A rewire that would collapse a polyline onto a single node (a degenerate self-loop the game's edge validator refuses) also forces the drop. After serialization a **final validation pass** (≤16 iterations to fixpoint) drops any remaining crash-class dangling `taxiway-segment`/`stand` entry and **reports** every other dangling owner (`taxi-navigation`, airways, runtime) rather than dropping it, then renumbers taxiway ordinals if anything was dropped. This pass also runs on a file that was **already** corrupt before this save: a pre-existing crash-class dangling count defeats the lossless no-op early-return so the offending entries get dropped instead of re-committed verbatim. Covered by `tests/integration/survivor_ref_gate.test.js` (reads a real game level via `tests/helpers/gameRoot.js` — skips cleanly when the game is not installed at `AC27_GAME_ROOT`). Triage scripts for this class: `tests/integration/scan_dangling_refs.cjs` (every dangling `$iref` grouped by owning PK and section, `--diff a.acl b.acl`), `scan_taxiway_health.cjs` (walks `taxiway-segment` `Nodes` lists the way `TaxiwaySegment2DFactory` does — flags dangling ids, `$iref:null`, non-node targets, positionless nodes) and `scan_level_health.cjs` (per-level entity + dangling-count table).
- **Ground Painter — non-fatal save warnings are surfaced, not swallowed:** `patchSceneryBlob(snapshotText, graph, blobTypeMap, meta, opts?)` takes an optional `opts.warnings` array; the `save-ground-painter-data` IPC handler passes one and returns it alongside `newText`/`geoResult` (also logged in the main process). A save that **succeeds** but dropped geometry now shows a `ground_painter_saved_with_warnings` modal listing the warnings (and still installs the new baseline) instead of silently losing it. 17 new i18n keys (zh + en in `src/utils/i18n.js`) back this: `ground_painter_fillet_error_click_near`, `..._fillet_tool_hint`, `..._fillet_dropped_leg|_stand|_runway`, `..._saved_with_warnings`, `..._save_failed`, `..._error_distinct_endpoints`, `..._error_area_min_vertices`, and the eight `ground_painter_writer_*` keys (`gate_rewired`, `gate_excised`, `gate_dropped_collapse`, `gate_dropped_unrepairable`, `new_segment_dropped`, `new_stand_dropped`, `last_resort_dropped`, `dangling_report`).
- **Ground Painter background image + opacity:** `GroundPainter.jsx` imports any raster image as a **map-anchored reference layer** behind the scenery (`bgImage` state `{src,naturalW,naturalH,anchorX,anchorZ,baseW,baseH,scale,offsetX,offsetY,opacity}`, `setBgImage`/`updateBgImage`). - **Ground Painter — polygon simplicity guard (Triangulator):** the game triangulates every area polygon and hard-fails the level load on a self-crossing outline (`ConstraintEdges... intersect!` → NullReferenceException). `src/acl/scenery_graph.js:polygonIsSimple(points)` (and the ESM mirror `src/components/EditorScreen/GroundPainter/polygon_simple.js` for the renderer, which cannot import the CJS acl module) rejects bowties: `_segProperCross` with bbox pre-filter, adjacent-edge sharing exempt, degenerate edges ignored. `GroundPainter.jsx` freezes a vertex drag at its last valid position when `!polygonIsSimple(newPoints)`; `electron/api-server.js:create_areas` validates every polygon the same way and returns `{success:false, error:'area outline crosses itself'}`.
- **Ground Painter — degenerate-edge guards:** the writer encodes vertices by coordinate — two consecutive positions closer than 1e-4 GU collapse into one vertex and the segment "joins vertex X to itself", which the save-time integrity check refuses. Guards: (1) `GroundPainter.jsx:applyDrag` node mode scans every polyline containing the dragged node and freezes the drag if any consecutive pair would colocate; (2) `fillet.js:attachVirtualFilletLeg` dedups the tangent polyline and drops a leg that would be <2 distinct positions, `applyVirtualFillet` pre-checks both legs anchoring at the same position (or same shared-position node) and rejects before mutating, and `repairGhostRefs` final sweep drops degenerate segments (self-loop or consecutive dup); (3) `scenery_write.js:patchSceneryBlob` referenced-node rescue keeps any `taxiway-node` still `$iref`'d by a surviving `runway`/`taxiway-segment`/`stand`/`taxi-navigation` (3-pass fixpoint), then `_gateSurvivorDanglingRefs` now covers `runway` thresholds too (unrepairable threshold drops the runway + its pavement strips via `droppedRunwayPhys`), and the `PhysicalRunway` registry + pavement-strip suppression removes orphan paint after a gate-dropped runway.
- **Ground Painter — runway/stand delete cascade + flight reconciliation:** a runway IS its pavement strips (`Name === physicalName`, `Flags=4`) + thresholds — `GroundPainter.jsx:deleteSelected` now cascades through `cascadeDeleteRunway` (records `meta.deletedPks` for strips + `deletedRunwayNames` for end/physical names, GCs strip + threshold nodes) and `recordDeletedStand` (records `deletedStandNames`), both for single and multi-select (box-select). `electron/api-server.js:delete_ground_objects` mirrors the cascade with orphan GC and `deleted*Names` bookkeeping; `move_ground_objects`/`move_ground_endpoint`/`rename_ground_object` (new MCP tools) move/rename segments/runways/stands through the same graph (runway moves carry coupled strips, renames validate `^[0-9]{1,2}[A-Z]?$` and uniqueness). `create_runways` now suffix-deduplicates heading-derived designations (`L/R` then `C`) against taken `physicalName`/end names so two runways never synthesize duplicate `$k: runway:<name>` keys ("found 0 named runways"). **Flight reconciliation** in `electron/main.js:save-ground-painter-data` after `writeAcl`: compares the saved file's stands/runways against the pre-save snapshot (truth = saved file, not graph — the writer may drop more than the graph shows), builds `runwayRename`/`standRename` maps (index-parallel `runwayOrigInfo`/`runwayOrigPk` + nose-position matching for stands, guarding that rename targets still exist in the saved file), remaps flights, purges any flight whose `Stand`/`Runway` existed pre-save but no longer resolves, rebuilds flight sections via `generateFullAcl` (with approach cache + `exportGameCSV` sync), and returns `purgedFlights`/`refsRemapped` alongside `newText` (when flight sections were rebuilt, `finalText = readAclText(filePath)` so the renderer's snapshot reflects the purge). Box-select/group-move thresholds use `move_ground_objects`.

## Schema

All `.acl` files use the **v4 schema** — a GATCARC4 binary container (introduced by a game update). v4 is the only format: there is no schema detection and no `isV4` flag anywhere in the code. A **v5 data update** (shipped with ZGSZ — `StreamingAssets/aircraft_profiles.csv` + per-level SceneryData filtering) keeps the container format but changes content: specs move to the global CSV (shared across all airports), `PhysicalName` moves inside `PhysicalRunwayStaticItem` (inline or `$iref` to inline), Area type shifts 30→31, and each level carries only a subset of STAR/SID/APPR/runways — the cache merges across every `.acl` in the airport (see `buildApproachCache` v5 merge). Every parse/extract/build path still goes through `buildPkIndex()` → `PKStaticEntities` + `$blobdoc` navigation.

- **Binary container:** Files are stored on disk as GATCARC4 binary (magic "GATCARC4", SHA-256 payload integrity, append checkpoint frames). `readAclText()` decodes to Odin JSON text; `writeAcl()` re-encodes preserving the on-disk format — but **every document is first renumbered by `src/acl/id_renumber.js`** (`renumberAclIds`): `$id` declarations and `$iref` references are rewritten to a **strictly ascending sequence in text order** using one shared counter per document, with `$blobdoc` values renumbered as independent documents (fresh 1..N) sharing a segment-wide old→new registry (so outer-document `aircraft:` stub entries can `$iref` ids declared inside a byte[] payload). The game's checkpoint reader (JsonDataReader) requires ascending ids in text order; the rebuild's construction-order allocation (wrapper $id 1123 before its inline Aircraft 1120) plus kept low ids after new high ones made the game misbind DockingAircraft inline values → `SetDockingTarget(null)` NullReferenceException per docked jetway at level init. **Dangling/forward `$iref` handling:** a `$iref` whose target is not yet declared is preserved verbatim and its value reserved (never re-allocated to a fresh `$id`) — the game reads a dangling `$iref` as null. The tradeoff is a same-scope forward `$iref` in a file with id gaps can silently misbind. Related: when `writeAcl` receives `options.originalText`, `renumberAclIds` repairs `$type` re-registration — ids recoverable from the original text's declarations are re-introduced as inline `N|Name` forms at the first surviving bare ref (armed only on the Ground Painter path: `scenery_write.js`/`electron/main.js` pass `originalText`; the flight-save path does not). `$eref`/`$fstrref`/`$guidref` are untouched (different id spaces). `countIdDescents(text)` is the diagnostic (violations/dups/max per scope, blobdoc-aware — it DOES descend into nested `$blobdoc` values; healthy game files score 0). Covered by `tests/integration/id_renumber.test.js`.
- **Flight plans:** Flight-plan entries live in `StaticData.$blobdoc.StaticItems.$rcontent` with `flight-plan:` key prefix. Uses `InitialArrival`/`InitialDeparture` field names. InBlockTime/TakeoffTime always 0 (game computes dynamically). `AirlineName` stores the 3-letter airline code (e.g. `"CDG"`), defaulted to the callsign prefix for new flights. The leg is chosen by the internal `isDeparture` flag (set at creation; the serializer falls back to `OffBlockTime` presence — `_isDepartureFlight()`).
- **Type numbering:** `$blobdoc` sections have **independent type numbering** from the outer document. Type N inside a `$blobdoc` can mean a completely different type than type N outside it. Both save and load paths maintain separate type maps (per segment in the save pipeline).
- **Frontend integration:** Hides InBlockTime/TakeoffTime columns. Skips time-order validation (InBlockTime/TakeoffTime always 0/unset). New flights skip InBlockTime/TakeoffTime defaults.
- **No pre-spawned aircraft:** Files have no WorldState section and no pre-spawned State=30 or State=5 aircraft. Approach/State-5 extraction functions (`extractApproachData`, `extractState5Data`) return empty.
- **Designator mapping — two-pass with jetway fallback + global CSV (v5):** `buildDesignatorMapping` cross-references `StaticItems` (flight-plan → Registration, AircraftType, Stand) with `RuntimeEntities` in two passes to build the `AircraftType → Designator` map. **Pass A** scans `aircraft:REG` entries for `Specification.Designator` (linked via Registration). **Pass B** scans `jetway:STAND` entries for `DockingAircraft.Specification.Designator` (linked via Stand → AircraftType from the static-item `Stand` field). This handles aircraft whose only runtime representation is inside a jetway's `DockingAircraft` rather than as a standalone `aircraft:REG` entry. Pass B resolves each jetway key through `jetwayKeyStandCandidates` (see below) so a sub-jetway ("it4-A7-1") whose spec is hosted only in its parent's stand form still maps to the flight-plan type. **v5:** when `StreamingAssets/aircraft_profiles.csv` exists, `loadGlobalSpecDB(airportDir)` seeds both `specDB` and `designatorMap` globally before the two-pass scan — the CSV is the single source of truth (`parseAircraftProfilesCsv` parses `AircraftType,Designator,AerodromeCode,WakeCategory,WheelBase,ModelOffset,WingSpan,DockingPositions,VR,ToL`; keys are indexed by both AircraftType and Designator). The scan then augments (never overwrites) the global maps and the save path falls back to generic defaults when a type is still missing (see fallback bullets).
- **Runway pairs from static PK entities:** `extractV4RunwayPairs(aclText)` (in `src/acl/utils.js`, re-exported via the parser facade) derives the runway-change pair options for the RunwayEditor from the static runway objects in `PKStaticEntities` — each physical runway ("4L/22R") appears as two `"$k": "runway:*"` entries sharing a `PhysicalName`, yielding the reciprocal pair `4L|22R` + `22R|4L`. `electron/main.js` calls `extractV4RunwayPairs` on the first ACL in `_collectAirportRunwayPairs` (`collectRunwayPairs` remains only as a fallback if extraction throws). Note the flag-clearing rule in `useEditorSaveActions.jsx`: `timelineModified.runway` must be cleared on save regardless of `runwayTimelinePath` (the ACL patch in `save-acl` always runs; most real levels have an empty `Config.runwayTimelineFile` → no sidecar JSON → previously the flag stayed set and back-navigation falsely reported unsaved changes).
- **Stand alias registration in designator mapping:** the `Stand → AircraftType` map used by Pass B registers **alias forms** of each flight-plan stand so the exact jetway-key lookup resolves — flight plans say `"31"` while jetway keys are `"31A"`/`"31B"`, or `"07"` vs `"7"`. For stands with a numeric prefix, aliases are: the raw string, the un-padded number, the zero-padded (2-digit) number, and each with `A`/`B` suffixes; **first-registered wins per alias** (flight-plan scan order). Non-numeric stands (e.g. `"it4-38"`) register only their exact string — no suffix aliases. Note: a stand's aliases claim its sibling sub-position names too (`"31"` claims `"31A"`+`"31B"`; `"1A"` claims `"1B"`), so when sibling jetways host different aircraft types the first-scanned type wins for the whole family.
- **Jetway-key → stand candidates (`jetwayKeyStandCandidates`, `src/acl/approach.js`, exported via the parser facade):** Jetway keys carry spatial suffixes the flight plans omit — sub-jetways `"it4-A7-1"`/`"it4-A7-2"` belong to parent stand `"it4-A7"`, and numeric stands are referenced as `"31A"`/`"31B"` by jetways but `"31"`/`"07"` by flight plans. - **Tokenizer `findKeyAtDepth` string-awareness fix:** `findKeyAtDepth(start, end, key, targetDepth)` only matches the search key at an opening quote that is OUTSIDE a string (`!inString` at `"`), instead of checking for the key text anywhere at the target depth. The key-match check moved into the quote handler before the `inString` toggle; escaped quotes (`\"`) are still skipped by the backslash rule.
- **State=5 ProgressRatio=0:** `_buildStandaloneAircraftEntry` writes constant `ProgressRatio: 0` (`STATE5_OUTPUT_PROGRESS_RATIO`) for State=5 (final approach) aircraft — the game recalculates path-based PR from PathPointList. Position/direction are still computed with the real time-based PR. State=30 entries keep their computed PR. Covered by `tests/integration/state5_output_pr.test.js`.
- **New flights: `isDeparture` flag + `AirlineName` code:** Newly created flights (UI factory `createDefaultFlight`, MCP `create_flights`) now carry `isDeparture` (true for departures) and `AirlineName` = the 3-letter airline code (the game stores codes, e.g. `"CDG"`/`"UAL"`, not display names). All 7 arrival/departure classification sites in `flight_plans.js` (static-items leg, stand-conflict validation, jetway rebuild, turnaround winner, runtime flight-plan/aircraft entries) go through `_isDepartureFlight()` — `isDeparture === true` OR non-empty `OffBlockTime` — so a missing flag can never silently serialize a departure as an arrival again. The serializer also falls back `AirlineName` to the callsign prefix. AirlineCode edits sync `AirlineName` via the cascade (renderer `flightCascade.js` + server `applyCascades`). Covered by `tests/integration/new_departure_save.test.js` (saves flag-less flights, asserts the departure leg + code roundtrip).

## Key Rules for Agents

1. **React + Vite + zustand stack.** Frontend uses ESM, JSX, and React hooks. No global-scope scripts.
2. **No TypeScript.** This is plain JS/JSX. Do not add `tsconfig.json` or convert files to `.tsx`.
3. **No linter/formatter.** Do not add ESLint, Prettier, or any linting config unless explicitly asked.
4. **Testing uses Vitest (component) + Playwright (E2E) + Node.js (integration).** Component tests go in `tests/components/`, electron-backend tests in `tests/electron/` (use `@vitest-environment node` + `require.cache` priming for CJS modules that require ESM SDKs), E2E specs in `tests/e2e/`, integration scripts in `tests/integration/`. Do not add Jest or Mocha.
5. **No npm dependencies for core logic.** The app uses only Node.js built-ins. Justify any new dependency.
6. **Preserve CommonJS for backend.** `electron/` and `src/acl/` use `require()`/`module.exports`.
7. **ESM for frontend.** `src/components/`, `src/hooks/`, `src/store/`, `src/utils/` use `import`/`export`.
8. **IPC for all file I/O.** The renderer never touches the filesystem. All reads/writes go through `electron/main.js` handlers.
9. **Return `{ success }` from IPC.** Every handler returns `{ success: true/false, error?: string }`.
10. **`_underscore` = private in backend.** Prefix internal functions with `_`. Export them anyway for testing.
11. **`snake_case.js` for backend, `PascalCase.jsx` for components.** Match existing conventions.
12. **No inline `style={{}}`.** Always extract CSS to the component's `.css` file.
13. **One `.css` per component.** Match the component filename.
14. **No `dangerouslySetInnerHTML`.** Use `safeHtml()` from `src/utils/safeHtml.jsx` to render i18n strings containing `<strong>`, `<em>`, or `<br>` as safe React nodes. It sanitises unknown tags and attribute injection as plain text.
15. **Use `readAclText()` / `writeAcl()` for all ACL I/O.** Never use `fs.readFileSync(path, 'utf-8')` or `fs.writeFileSync(path, text, 'utf-8')` for `.acl` files. Always go through `gatcarc.js` to transparently decode/encode the GATCARC4 binary container. This applies to `electron/main.js`, all backend modules, and all integration tests.
16. **Use `resolveConfigTime()` for config time display.** Every consumer of ACL config time (startTime/endTime) must use `resolveConfigTime(rawText)` from `src/acl/config.js` — not `_extractConfig()` directly. `resolveConfigTime` applies the GameTime.CurrentDateTime override (post-warmup time), rounded UP to the next whole minute via `roundSecondsToMinute()` from `src/utils/timeUtils.js`. This is the single source of truth. All IPC handlers that read config (`get-file-info`, `load-acl`, `save-acl`, `import-zip`, `restore-latest-backup`, `load-timelines`) already use it.
17. **Update the facade.** New backend modules must be re-exported through `src/acl/parser.js`.
18. **Build locally with `node build.js`** on Windows, never `npm run build:win` (local only — CI uses `npm run build:win` for cross-platform builds).
19. **Bump `CACHE_VERSION` when cache.json schema changes.** Any change to the structure of `approachData`, `fileTypeMaps`, `state5ParamsMap`, `taxiwayPaths`, `sidPaths`, `missedAppPaths`, `airwayNodes`, `starWaypoints`, `allAclTexts` merge, or new top-level keys in cache.json MUST bump `CACHE_VERSION` in `src/utils/constants/timing.js` (re-exported via `src/utils/constants/index.js` and `src/acl/constants.js` for CJS backward compat). Stale caches silently corrupt saves. **Current `CACHE_VERSION` is 25 (23 → 25 for the Ground Painter's `_groundAnchor` + taxiway OSM pool cache data; 24 skipped)**. Note: `saveTimeOffsets` and `typeMap` are build-time-only and are no longer serialized.
20. **Version tags for releases.** Version tags use `v<MAJOR>.<MINOR>.<PATCH>` (e.g. `v1.2.0`). Keep `package.json` `version` and the git tag in sync. The user decides when to bump; you can re-tag the same version to include new changes.
21. **Keep documentation in sync.** After any significant change, update ALL of:
 - **This skill** (`.claude/skills/ac27-editor/SKILL.md`) and its reference files
 - **README.md**
 - **`tests/README.md`** — whenever tests are added/removed, update the test counts (line 9, line 18, line 22), the file table (add/remove rows), MapWindows file/test counts (line 34), and expected outcomes (lines 44–53). Stale test docs mislead contributors about what's covered.
22. **UDP listener lifecycle is managed by main process.** `startUdpListener()` is called in `app.whenReady()` after `createWindow()`, `stopUdpListener()` in `will-quit`. The listener auto-reconnects on socket errors (2s delay). Do not create multiple listeners or start/stop from the renderer.
23. **Map windows are separate BrowserWindow instances.** They are NOT React components in the main renderer. Track them in `groundMapWindows`/`airMapWindows`/`flightStripsWindows` Maps (keyed by ICAO). Always check for existing windows before creating (focus if exists). Clean up Map entries in the `closed` event handler. Each window loads the same Vite SPA with query params (`?window=groundMap&airport=XXXX`, `?window=airMap&airport=XXXX`, or `?window=flightStrips&airport=XXXX`).
24. **UDP state push handles cleanup.** The `udp-aircraft-state` IPC event is pushed to ALL open map windows every 200ms. Map window components subscribe via `useUdpAircraftState()` hook which wraps `onUdpAircraftState`/`offUdpAircraftState`. Always unsubscribe in `useEffect` cleanup to prevent stale callbacks or memory leaks.
